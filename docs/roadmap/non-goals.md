# 非目标与范围控制

## 为什么需要非目标

Knowledge system 很容易无限扩张。本文件用于保护 MVP，任何新增大组件都应先证明它解决的是当前真实瓶颈。

## 当前非目标

- 构建通用搜索引擎或全网爬虫。
- 替代 Zotero、Notion、Obsidian 等资料管理工具。
- 构建企业级多租户知识平台。
- 一开始就完成复杂 Knowledge Graph / Ontology。
- 对所有领域做统一 Truth Discovery。
- 用 Agent 自主循环替代确定的 Pipeline。
- 将所有原始文档都向量化并依赖向量数据库。
- 追求“零人工”而牺牲可审计性。
- 在没有真实并发需求前拆微服务。

## 新功能进入条件

新增基础设施或核心模块必须至少满足一个条件：当前 MVP 无法正确表达；性能瓶颈已测量；上层项目有明确需求；现有实现造成不可接受的维护成本；或新的可靠性要求无法通过简单方案满足。
